# Fuwari 运行时页面中英双语设计

## 目标

在不改变任何页面 URL 的前提下，为博客页面 UI 提供简体中文和英文切换。默认显示简体中文，访客选择会被浏览器记住。文章标题、正文、分类、标签和文章 URL 保持原样，不自动翻译。

## 非目标

- 不增加 `/zh/`、`/en/` 等语言路由。
- 不要求文章存在一一对应的中英文版本。
- 不在访客浏览文章时实时调用 AI 翻译服务。
- 本阶段不改变内容集合和文章 Frontmatter 结构。

## 当前状态

Fuwari 已有 `en`、`zh_CN` 等翻译表，但 `i18n()` 读取全局 `siteConfig.lang`，因此语言在构建时固定，访客无法在浏览器中切换。

## 用户体验

- 首次访问默认使用简体中文。
- 导航栏增加紧凑的 `中 / EN` 切换控件，桌面端和移动端均可访问。
- 切换后 URL 和当前滚动位置不变，页面 UI 立即更新。
- 选择写入 `localStorage`，后续访问和站内跳转继续使用该语言。
- 切换时同步更新 `<html lang>`：中文为 `zh-CN`，英文为 `en`。
- 文章内容不受 UI 语言切换影响。

## 技术方案

### 1. 语言状态

新增运行时语言模块，支持：

```ts
type UiLanguage = "zh_CN" | "en";
```

存储键固定为 `fuwari-ui-language`。读取到未知值、存储不可用或脚本异常时，统一回退到 `zh_CN`。

### 2. 避免首屏语言闪烁

在基础布局的 `<head>` 中加入最小内联初始化脚本，在页面绘制前读取本地选择并设置：

- `document.documentElement.dataset.lang`
- `document.documentElement.lang`

默认 HTML 仍构建为中文，因此脚本失败时页面也保持可读。

### 3. 可切换的翻译节点

新增 `LocalizedText.astro` 组件。组件接收现有 `I18nKey`，构建时输出中文文本，并为节点添加 `data-i18n-key`。运行时语言模块使用现有翻译表更新所有带该属性的节点。

对 `title`、`aria-label`、输入框 `placeholder` 等属性文本，使用显式的 `data-i18n-attr` 元数据更新，避免只翻译可见文本而遗漏无障碍信息。

逐步将现有直接调用 `i18n(...)` 的页面 UI 替换为该组件或属性辅助函数。文章渲染的数据不加翻译标记。

### 4. 语言切换器

新增无框架依赖的语言切换组件并挂载到导航栏：

- 当前语言有明确选中状态。
- 使用 `<button>`，带准确的 `aria-label` 和 `aria-pressed`。
- 点击后写入 `localStorage`、更新根节点语言属性、更新所有翻译节点，并派发 `fuwari:language-change` 自定义事件。
- 样式沿用现有导航栏、圆角和 hover/focus 规范，不引入新的 UI 库。

### 5. Astro 页面切换兼容

Fuwari 使用页面过渡时，新页面 DOM 会替换。运行时模块在以下时机重新应用当前语言：

- 首次加载
- `astro:page-load`
- `fuwari:language-change`

事件绑定必须可重复执行且不会叠加监听器。

### 6. 可选的站点个性化文案

`title`、`subtitle`、个人名称和简介继续兼容普通字符串，同时允许配置为：

```ts
{
  zh_CN: "中文文案",
  en: "English copy"
}
```

普通字符串在两种 UI 语言下保持不变，避免破坏上游配置兼容性。该能力只用于站点界面文案，不用于文章内容。

## 数据流

1. 浏览器加载页面。
2. `<head>` 初始化脚本读取 `fuwari-ui-language`，无有效值则使用 `zh_CN`。
3. 页面加载完成后，运行时模块从翻译注册表读取对应语言文本并更新标记节点。
4. 用户点击语言切换器。
5. 新语言写入存储，根节点、UI 文本、可访问属性和控件状态同步更新。
6. Astro 站内跳转完成后，再次把已选择语言应用到新 DOM。

## 错误处理

- `localStorage` 读写使用 `try/catch`，隐私模式或禁用存储时仅在当前页面生效。
- 不存在的翻译键回退到中文，再回退到键名，避免渲染空白。
- 无 JavaScript 时网站仍以中文完整工作。
- 切换器初始化失败不得阻止导航和文章阅读。

## 测试与验收

### 自动检查

- 语言值校验和回退逻辑单元测试。
- 翻译键在中英文表中均存在的完整性测试。
- DOM 翻译函数覆盖文本节点、属性文本和未知键。
- `pnpm check`、`pnpm build` 通过。

### 手工验收

- 首页、归档、关于、搜索、标签和文章详情页均可切换。
- URL、文章正文、标题、标签和分类不随 UI 语言变化。
- 刷新页面、打开新页面和 Astro 站内跳转后语言保持一致。
- 无明显首屏语言闪烁。
- 桌面和移动导航均可操作，键盘焦点清晰，读屏标签正确。
- 清除存储或写入非法语言值后恢复中文默认值。

## 后续可选功能：AI 翻译草稿

后续可单独增加本地命令或 GitHub Action，把某篇 Markdown 文章翻译为新的草稿文件，并保留 Frontmatter、代码块、链接与图片。该功能不进入本阶段，也不会在浏览器前端暴露模型 API Key。
